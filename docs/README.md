## 1. Идея игры

Простая текстовая RPG в формате Telegram-бота. Герой перемещается по локациям, ищет противников, сражается по пошаговой боевой системе на основе кубика, получает награду за победу и прокачивает характеристики. Первая версия — чистый PvE на одной локации с тремя противниками; PvP заложено в архитектуру, но не реализуется в MVP.

**Ключевая метафора, которой подчинена вся боевая механика:** бой должен ощущаться как игра по переписке — каждое действие игрока буквально бросает кубик и сразу видит результат, а не читает готовый отчёт о случившемся.

---

## 2. Архитектурные принципы (сквозные, действуют на весь проект)

- **Клиент-серверная архитектура.** Telegram-бот — тонкий клиент, вся игровая логика и вычисления — на HTTP-бэкенде. Бот не хранит и не считает ничего игрового, только инициирует запросы и отображает готовый результат.
- **`core/` — чистые функции без зависимостей.** Ядро игровой логики (бой, прогрессия) не знает про HTTP, БД, Telegram. Тестируется и симулируется независимо.
- **Пошаговая обработка.** Один HTTP-запрос = один шаг/ход. Состояние живёт в БД между запросами, не в памяти одного вызова.
- **Единая механика PvE и PvP.** Боевое ядро не различает, управляется ли сторона игроком или ботом — разница только в том, кто инициирует следующий шаг. PvP пока не реализуется, но архитектура его не блокирует.
- **Рендеринг текста отделён от логики.** `core/` считает структурированные факты (какие грани выпали, какой урон) → БД хранит факты → отдельный слой (`api/rendering.py`) превращает факты в готовый текст → бот только показывает. Это сохраняет переносимость на другой фронтенд/язык без изменений в игровой логике.
- **Все правила объясняются один раз, через `/rules`.** Сами экраны игры не содержат пояснений и подсказок — предполагается, что игрок уже ознакомлен с механикой.

## 4. Характеристики персонажа — очень кратко

| Стат | Роль |
|---|---|
| **HP** | Независимый ресурс. 0 — поражение. |
| **Здоровье** | Прокачиваемый стат, определяет `HP_max`. Не влияет на скорость регенерации. |
| **Сила** | Детерминированный урон. Единственная полностью предсказуемая характеристика. |
| **Ловкость** | Вероятность полного уворота от удара. Элемент случая, не мастерства. |
| **Удача** | Двойной удар и возможность побега при критичном HP. Редкие благоприятные развилки. |

Подробности и формулы — в `combat_mechanics.md`, §2-7.

## 5. Игровой цикл — очень кратко

```
/start → /rules (опционально) → Начать игру (создание персонажа, гибрид: база + пул очков)
  → Экран статов
  → Искать противника (бросок d10: 60% мышь / 30% волк / 10% кабан)
  → Определить инициативу + обстоятельство → Вступить в бой / Отступить
  → Цикл раундов: Атаковать / Защищаться (каждое нажатие — бросок(и) кубика с видимым числом)
  → Завершение боя (победа / поражение / побег) → награда (только при победе)
  → Регенерация HP — ленивый пересчёт по времени, без фоновых процессов
  → Экран статов → снова "Искать противника" или "Прокачать статы"
```

Полные макеты экранов — в `gameplay_loop_mvp.md`, §9.
