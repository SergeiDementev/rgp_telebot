# Игровой цикл MVP — согласованные принципы

Документ описывает полный цикл первого прототипа игры поверх боевого ядра (см. `combat_mechanics.md`). Здесь — всё, что происходит ВНЕ самого боя: создание персонажа, экраны, прогрессия, регенерация.

---

## 1. Вход в игру

- **`/start`** — приветственное сообщение с краткой информацией об игре и её принципах. Не создаёт персонажа.
  - Если у пользователя уже есть персонаж — повторный `/start` не пересоздаёт его, просто показывает приветствие снова.
- **`/rules`** — отдельная команда с полным объяснением механик (бой, статы, обстоятельства, побег, регенерация HP). Единственное место, где механики объясняются подробно — сами экраны боя и меню остаются лаконичными, без встроенных пояснений/подсказок (см. §9).
- **Отдельная команда/кнопка "Начать игру"** — создаёт персонажа, если его ещё нет.
- **Никнейм** — берётся из имени/username Telegram, отдельного ввода имени героя нет.

---

## 2. Создание персонажа — гибридное распределение статов

- Фиксированная база одинакова для всех персонажей.
- Сверху даётся **пул очков**, которые игрок распределяет сам через кнопки (тот же интерфейс, что и при левел-апе, см. §5).

**Черновые стартовые значения (параметры для теста):**

```
База:  Здоровье = 3, Сила = 3, Ловкость = 3, Удача = 1
Пул для распределения при создании: 5 очков
```

Распределение — по одному клику за раз ("+1 к Силе", "+1 к Ловкости" и т.д.), без ввода произвольных чисел.

---

## 3. Стат "Здоровье" → HP

Здоровье — отдельная прокачиваемая характеристика, не совпадающая с самим HP напрямую.

```
HP_max = 20 + Здоровье × 10
```

**При увеличении стата Здоровье:**
- `HP_max` растёт по формуле.
- `HP_current` **не меняется** (остаётся тем же абсолютным числом) — то есть процент заполнения HP-бара после прокачки Здоровья падает. Это осознанное решение, не баг.

---

## 4. Экран статистики персонажа

Переиспользуемый шаблон, используется и после создания персонажа, и после боя, и в меню статов.

```
🧙 <ник>
🏅 Уровень: <N>
❤️ HP: <current>/<max>
💪 Сила: <N>
🤸 Ловкость: <N>
🍀 Удача: <N>
🏆 Победные очки: <N> (до след. уровня: <N>)

[Искать противника]  [👤 Меню игрока]
```

**"👤 Меню игрока" (переименовано 2026-09-17, docs/notes.md п.30)** — раньше называлась "📊 Прокачать статы", та же точка входа, экран за ней расширен секциями золота/лута/зелий (см. §5).

## 5. Уровни и прокачка

- **Победные очки** — одновременно и мера общего прогресса (накопительно, не тратятся), и триггер для получения очков прокачки.
- При пересечении порога следующего уровня — персонаж получает **+2 очка прокачки** (`STAT_POINTS_PER_LEVEL`, откалибровано на этапе 2 — см. `backend_plan.md` §8), которые игрок распределяет сам (кнопки "+1 к Силе / Ловкости / Удаче / Здоровью"). При скачке сразу через несколько уровней (крупная награда) очки суммируются за все пройденные уровни.
- Победные очки не расходуются на прокачку напрямую — они только копятся и двигают уровень.

**Формула порогов — растущий шаг:**

```
threshold(N) = threshold(N-1) + 4 × N

Уровень 2 →  8 очков   (0 + 8)
Уровень 3 → 20 очков   (8 + 12)
Уровень 4 → 36 очков   (20 + 16)
Уровень 5 → 56 очков   (36 + 20)
...
```

Константа "4" — параметр для калибровки на плейтесте.

### Макет экрана "Меню игрока" (добавлено 2026-09-17 — docs/notes.md п.30)

Тот же интерфейс используется и при создании персонажа (§2, с начальным пулом), и при обычном обращении с главного экрана статов (кнопка "👤 Меню игрока", §4) — различается только заголовок/контекст, механика распределения очков идентична. Расширен секциями золота, лута и зелий — экономика, откалиброванная в `scripts/simulate_combat_economy.py`/`simulate_boss.py` (docs/notes.md пп.26-29), переносится в саму игру той же схемой (продажа лута мгновенная, покупка зелий с капами).

**Принципы (без изменений для очков прокачки):**
- Применение мгновенное по клику — нажал "+1 к Силе"/"Продать весь лут"/"Купить зелье" → действие сразу применено. Никакого отдельного подтверждения.
- **Без отмены/перераспределения** уже потраченных очков и уже проданного лута — решение необратимо.
- HP_max показывается в скобках только у Здоровья (прямая понятная формула) — у Силы/Ловкости/Удачи эффект не сводится к одному наглядному числу, там просто сырое значение стата.
- Сообщение обновляется редактированием на месте (`editMessageText`), тот же принцип, что и в бою — для всех трёх типов действия (прокачка/продажа/покупка), без новых сообщений.

**Порядок секций сверху вниз:** статы → победные очки/золото/очки прокачки → лут → зелья → кнопки действий.

```
👤 Меню игрока

🏅 Уровень: 9
💪 Сила: 12
🤸 Ловкость: 9
🍀 Удача: 4
❤️ Здоровье: 9  (HP max: 110)

🏆 Победные очки: 176 (до след. уровня: 40)
💰 Золото: 23
Доступно очков прокачки: 2

📦 Лут: Мышиная шкурка ×14, Клык волка ×3
🧪 Зелья: Малое ×2, Большое ×1

[+1 Сила]  [+1 Ловкость]
[+1 Удача]  [+1 Здоровье]

[💰 Продать весь лут]

[🧪 Купить малое (8 зол.)]  [🧪 Купить большое (50 зол.)]

[⬅️ Назад]
```

**Если лута нет:** строка меняется на "📦 Лут: пока нет", кнопка "Продать весь лут" отсутствует (см. паттерны видимости ниже).
**Если зелий нет вообще (оба по нулю):** строка меняется на "🧪 Зелья: пока нет" (кнопки покупки при этом остаются — они не про то, что уже есть, а про то, что можно купить).
**Если очков прокачки нет:** кнопки "+1" отсутствуют, вместо строки "Доступно очков прокачки: N" — "Нет свободных очков. Получишь ещё при следующем уровне (до след. уровня: N победных очков)" (как и раньше).

#### Три паттерна видимости кнопок — разные не случайно, не унифицировать

1. **"+1 <стат>"** — кнопка **полностью исчезает**, если `unspent_stat_points == 0` (уже реализовано, не менять). Действие в принципе невозможно без очков — держать кнопку видимой нечем оправдать, только спровоцировать лишний клик по "мёртвой" кнопке.
2. **"💰 Продать весь лут"** — кнопка **полностью исчезает**, если инвентарь лута пуст. Та же логика, что и у пункта 1: действие невозможно (нечего продавать), а не просто временно невыгодно.
3. **"🧪 Купить малое/большое"** — кнопки **всегда видимы**, даже когда покупка сейчас недоступна; вместо исчезновения — метка неактивности, и она различается по причине:
   - не хватает золота → цена в подписи кнопки сама показывает, сколько нужно ("Купить малое (8 зол.)") — этого достаточно как обратной связи, отдельная пометка не нужна;
   - достигнут потолок капа (5 малых / 3 больших) → подпись меняется на "уже максимум", чтобы не путать с нехваткой золота (это две разных причины бездействия, игрок должен понимать, какая именно).

   Отличие от паттернов 1-2: там действие в принципе **невозможно** прямо сейчас и не является целью, к которой игрок идёт. Здесь — ровно наоборот: покупка зелья часто **цель, к которой копится золото** несколько боёв подряд (см. docs/notes.md п.27 про раннюю экономику) — исчезающая кнопка прятала бы от игрока сам ориентир "сколько ещё копить" и "куда я вообще расту". Кнопка остаётся на месте как постоянный ориентир, просто временно неактивна.

**Порядок кнопок:** `[+1 к статам] → [Продать весь лут] → [Купить малое] / [Купить большое] → [⬅️ Назад]`.

**Экран при создании персонажа** — тот же макет, что раньше (без секций золота/лута/зелий: у нового персонажа их физически ещё нет, показывать нечего), другой заголовок и кнопка выхода:

```
🧙 Создание героя
Осталось очков: 5

💪 Сила: 3
🤸 Ловкость: 3
🍀 Удача: 1
❤️ Здоровье: 3  (HP max: 50)

[+1 Сила]  [+1 Ловкость]
[+1 Удача]  [+1 Здоровье]

[✅ Начать приключение]
```

Кнопка "Начать приключение" доступна сразу, распределять весь пул до конца необязательно — нераспределённые очки не сгорают и не блокируют старт, а просто переносятся в `unspent_stat_points` и ждут в обычном "Меню игрока" после первого же боя.

## 6. Поиск противника

Игрок нажимает "Искать противника" → сервер бросает кубик d10, определяющий, кто встретится. С пересмотра 2026-09-16 пропорции зависят от **уровня персонажа** (`core/progression.py::calculate_encounter_faces`) — на низких уровнях мышь встречается чаще (лёгкий старт), на высоких смещается к кабану (иначе к концу игры становится скучно, мышь уже не интересна). Волк держится постоянно на 30%.

```
d10, зависит от уровня персонажа (таблица по диапазонам, не формула — см. ниже):
  Уровень 1-2  → 1-6 Мышь (60%) / 7-9 Волк (30%) / 10 Кабан (10%)
  Уровень 3-4  → 1-5 Мышь (50%) / 6-8 Волк (30%) / 9-10 Кабан (20%)
  Уровень 5-6  → 1-4 Мышь (40%) / 5-7 Волк (30%) / 8-10 Кабан (30%)
  Уровень 7-8  → 1-2 Мышь (20%) / 3-5 Волк (30%) / 6-10 Кабан (50%)
  Уровень 9-10 → 1   Мышь (10%) / 2-4 Волк (30%) / 5-10 Кабан (60%)
```

(Пересмотрено на плейтесте 2026-09-16, второй раз в этот же день: старт медленнее — 60/30/10 вместо 50/30/20 на 1-2 уровне, конец резче — 10/30/60 вместо 20/30/50 на 9+ уровне. Переход **неравномерный по замыслу** — между 5-6 и 7-8 уровнем двойной шаг (доля мыши падает с 40% сразу до 20%, а не до 30%) — это не побочный эффект формулы, значения заданы таблицей по диапазонам (`ENCOUNTER_FACES_BY_LEVEL_BAND`, `core/progression.py`), не интерполяцией. Волк по-прежнему держится постоянно на 30% на всех уровнях.)

Пропорции по-прежнему черновые, легко скорректировать, если после плейтеста частота встреч покажется неподходящей. Средняя награда за встречу выросла с ~1.8-кратного разброса (старт vs конец) до ~2.9-кратного — обсуждали отдельно, планируется компенсировать шкалой перехода между уровнями (`LEVEL_THRESHOLD_STEP_DEFAULT`, §5), решение по этому пока не принято.

Статы мышь/волк/кабан откалиброваны на этапе 2 (`backend_plan.md` §8, прогонами `scripts/simulate_combat.py`) и зафиксированы в `content/enemies.json`:

```
Мышь:  HP=20,  Сила=5,  Ловкость=2, Удача=1
Волк:  HP=50,  Сила=12, Ловкость=6, Удача=2
Кабан: HP=70,  Сила=11, Ловкость=6, Удача=2
```

## 7. Результат боя и награда

- **Фиксированная награда победными очками по типу моба** (черновые значения):

```
Мышь  = 1 очко
Волк  = 5 очков
Кабан = 15 очков
```

- **Наказания за поражение или побег нет.** Персонаж просто восстанавливает HP как обычно (см. §8), победные очки не теряются.
- Исходы `defeat`, `player_fled`, `enemy_fled` (см. `combat_mechanics.md`, §10) не дают награды, но и не откатывают прогресс.

## 8. Регенерация HP — ленивый пересчёт по времени

**Принцип:** никакого фонового процесса или таймера на сервере. Хранятся только `hp_current` и `last_hp_update_at`. Актуальный HP вычисляется **в момент любого обращения** игрока к боту (открыл меню, нажал кнопку, начал бой) — пересчитывается разница во времени и досчитывается регенерация, будто она шла непрерывно.

```python
REGEN_PER_SECOND = 1  # фиксировано для всех; стат Здоровье влияет ТОЛЬКО на hp_max,
                       # не на скорость регенерации

def get_current_hp(hp_current, hp_max, last_update_at, now, regen_per_second=REGEN_PER_SECOND):
    elapsed_seconds = (now - last_update_at).total_seconds()
    regenerated = math.floor(elapsed_seconds * regen_per_second)  # округление вниз — HP всегда целое
    return min(hp_current + regenerated, hp_max)

def time_to_full_hp(hp_current, hp_max, regen_per_second=REGEN_PER_SECOND):
    missing = hp_max - hp_current
    if missing <= 0:
        return 0
    return missing / regen_per_second  # в секундах
```

- Скорость намеренно высокая (1 HP/сек) — при текущем масштабе HP (десятки-сотни) это даёт кулдаун порядка секунд-минут даже после тяжёлого поражения. Осознанное решение: пока в игре нет других активностей кроме боя (и распределения статов, которое не блокируется регенерацией) — долгая пауза только фрустрирует, не добавляя стратегической глубины.
- Регенерация округляется **вниз** до целого HP (пересмотрено на плейтесте 2026-09-15) — реальное время между запросами почти никогда не кратно секунде, без округления HP оставался бы дробным даже между боями (где сам урон в бою теперь тоже целый, см. `combat_mechanics.md` §3).
- **Идти в бой не на полном HP разрешено** — никаких искусственных блокировок, риск — на усмотрение игрока.
- Открытие меню прокачки статов **не приостанавливает** регенерацию — она в принципе не "идёт" как процесс, а пересчитывается по факту обращения, так что не имеет значения, в каком меню находится игрок.

### Сообщение после боя

```
⚔️ Бой окончен! Ты победил Волка.
🏆 +5 победных очков (всего: 23)

❤️ HP: 40/60
⏳ Полное восстановление через: ~20 сек.

[🔄 Обновить]  [🔍 Искать противника]  [👤 Меню игрока]
```

- Кнопка **"Обновить"** не запускает отдельную механику — это то же самое обращение к серверу, что и любое другое действие: пересчитывает `hp_current` по формуле выше и переотправляет то же сообщение с актуальными цифрами (через редактирование существующего сообщения, а не рассылку новых). В реализации (`bot/handlers/combat.py`) это упрощено до отдельного компактного блока "❤️ HP: X/Y" + таймер, без заголовка исхода боя ("Ты победил...") — тот был одноразовым текстом из ответа `/turn` и нигде не хранится; восстанавливать его в боте означало бы дублировать в `bot/` решение `api/rendering.py` о том, как формулировать исход.
- Проактивных сообщений о восстановлении (бот сам ничего не присылает по таймеру) — нет. Обновление только по явному действию игрока.

## 9. Отображение боя — макеты экранов

**Общий принцип: каждое нажатие игрока = осязаемый бросок (или связка бросков одного его действия), а не пассивное чтение готового отчёта.** Кнопка не просто продвигает бой дальше — она соответствует конкретному игровому действию игрока ("Искать противника", "Атаковать", "Защищаться"), и по нажатию сразу разворачивается результат этого действия. Технически весь ход может быть посчитан сервером заранее за один вызов — но раскрытие игроку всегда идёт по кнопке конкретного действия, а не автоматической прокруткой.

**Правило форматирования — любой бросок кубика всегда показывает выпавшее число, а не только словесный итог.** Это касается вообще всех бросков без исключения: поиск противника, инициатива, обстоятельство, проверка удачи, атака, уворот, попытка побега. Формат: `<число> → <результат>`.

```
Правильно:   🎲 Проверка удачи: 3 → двойного удара нет.
Неправильно: 🎲 Проверка удачи... не в этот раз.
```

**Техническая деталь отображения:** сообщения внутри одного боя редактируются (`editMessageText`), а не рассылаются новыми — чат остаётся компактным. Финальное сообщение с результатом боя — новое, чтобы сводка не потерялась под дальнейшими действиями и оставалась в истории чата.

**Никаких игровых подсказок и пояснений механик внутри экранов боя.** Все правила объясняются один раз, отдельно, по команде `/rules` (см. §1). Кнопки и сообщения в бою остаются лаконичными.

### Шаг 2 — инициатива и обстоятельство (одно нажатие на оба броска)

Инициатива и обстоятельство — неразрывная цепочка одного действия ("открыть карты перед боем"), разворачиваются одним нажатием.

```
[Нажал "⚔️ Определить инициативу"]

🎲 Инициатива: ты — 7, волк — 4. Ты ходишь первым!

🎲 Обстоятельство: 9 → ⚡ "Прилив адреналина!"
Твоя Сила увеличена на этот бой (×1.2)

[⚔️ Вступить в бой]   [🏃 Отступить]
[⚡ Автобой]   [🏁 Показать результат]
```

Если инициативу выиграл противник — обстоятельство кидает он, кнопки те же:

```
[Нажал "⚔️ Определить инициативу"]

🎲 Инициатива: волк — 9, ты — 2. Волк атакует первым!

🎲 Обстоятельство: 2 → ⚡ "Скользкая земля"
Сила волка увеличена на этот бой (×1.2)

[⚔️ Вступить в бой]   [🏃 Отступить]
[⚡ Автобой]   [🏁 Показать результат]
```

Кнопка **"Отступить" присутствует всегда**, независимо от исхода обстоятельства (см. `combat_mechanics.md`, §7-8) — сложность попавшегося противника сама по себе достаточная причина для права уйти.

**"⚡ Автобой" (добавлено 2026-09-16, docs/notes.md п.3)** — третья опция на этом же экране, не отдельная настройка: выбирается заново для каждого конкретного боя. Вступает в бой и дальше сам проигрывает ходы с паузой ~1.5 сек между ними, имитируя ручное нажатие (сообщение реально обновляется на каждом ходу, не одним итогом в конце) — останавливается на решении "сбежать по HP" или на конце боя.

**"🏁 Показать результат" (добавлено 2026-09-17, docs/notes.md п.25, черновое название)** — четвёртая опция там же, та же механика, что у автобоя, но без анимации: крутит все ходы молча (без пауз, без правки сообщения на каждом шаге) и показывает только итог — либо паузу на решение "сбежать/биться дальше", либо конец боя. Для боёв с лёгкими противниками (мышь), которые скучно читать по шагам.

### Шаг 3 — экран вступления в бой

```
[Нажал "⚔️ Вступить в бой"]

🐺 Волк: 100/100 ❤️
🧍 Ты: 85/85 ❤️

[🎲 Атаковать]
```

В реализации (`bot/handlers/combat.py`) HP-бары обеих сторон на этом экране пока не выводятся — `POST /combat/{id}/confirm` возвращает только текст "⚔️ Ты вступаешь в бой!" и кнопку следующего хода. Не архитектурное ограничение: бот уже получал бы нужные числа из `GET /character` и `GET /combat/{id}`, просто не собран как отдельный шаг — можно добавить позже.

### Цикл раунда — две отдельные фазы, каждая по своему нажатию

Раунд разбит на **фазу атаки игрока** и **фазу защиты игрока** (=ход противника) — два разных нажатия, оба активны для игрока, не пассивное наблюдение за половиной раунда.

**Фаза атаки (кнопка "Атаковать"):** проверка удачи игрока → атака игрока → уворот противника → урон.

```
[Нажал "🎲 Атаковать"]

🎲 Проверка удачи: 3 → двойного удара нет.
🗡️ Твоя атака: 8 → 80% силы удара.
🛡️ Волк уворачивается: 4 → не вышло!
💥 Ты наносишь 68 урона.

🐺 Волк: 32/100 ❤️

[🛡️ Защищаться]
```

**Фаза защиты (кнопка "Защищаться"):** проверка удачи противника → атака противника → уворот игрока → урон.

```
[Нажал "🛡️ Защищаться"]

🎲 Волк проверяет удачу: 5 → двойного удара нет.
🗡️ Атака волка: 6 → 60% силы.
🛡️ Твой уворот: 8 → увернулся!
✅ Урон полностью пропущен.

🧍 Ты: 85/85 ❤️

[🎲 Атаковать]
```

**Двойной удар** не создаёт отдельную фазу — он остаётся внутри той же фазы, где случился (проверка удачи — один раз в начале хода атакующей стороны, см. `combat_mechanics.md` §5), просто удар-уворот повторяется дважды перед переходом к следующей фазе:

```
[Нажал "🎲 Атаковать"]

🎲 Проверка удачи: 9 → ✨ УДАЧА! Двойной удар!

🗡️ Удар 1: 9 → 90% силы. 🛡️ Волк уворачивается: 3 → не смог! 💥 72 урона.
🗡️ Удар 2: 5 → 50% силы. 🛡️ Волк уворачивается: 7 → увернулся!

🐺 Волк: 8/100 ❤️

[🛡️ Защищаться]
```

### Зелья — кнопка на этапе атаки (добавлено 2026-09-17, docs/notes.md п.33)

Зелье — явное решение игрока кнопкой, не автоматика по порогу HP. Доступно **только в ручном бою**, только на фазе атаки игрока (не на "Защищаться", не на паузе "сбежать/биться дальше"), и **только в автобою/"Показать результат" его вообще нет** — те режимы не показывают промежуточных кнопок, а зелье требует явного клика.

```
[Нажал "🎲 Атаковать" — экран уже показан, зелья куплены]

🧍 Ты: 22/85 ❤️   🐺 Волк: 40/100 ❤️

[🎲 Атаковать]
[🧪 Малое]   [🧪 Большое]
```

Кнопка "🧪 <размер>" есть, только если этот размер зелья куплен (§ "Меню игрока") — если куплен только один размер, вторая кнопка просто отсутствует; если ни одного — нет всего ряда. Использование зелья **заменяет атаку в этот ход** (не бесплатное дополнение к удару) — сразу передаёт ход противнику:

```
[Нажал "🧪 Большое"]

🧍 Ты: 22/85 ❤️   🐺 Волк: 40/100 ❤️

🧪 Большое зелье: +25 HP.

[🛡️ Защищаться]
```

Лимит — **одно зелье за бой, общий на оба размера** (не "1 малое + 1 большое"): после использования кнопки "🧪 ..." пропадают до конца этого боя, независимо от того, что ещё осталось в инвентаре.

### Возможность побега по HP-порогу

Проверяется в начале хода атакующей стороны (перед её собственной фазой — перед "Атаковать" для игрока, перед "Защищаться" для хода противника, если критично низкое HP уже у него). Появляется только при успешном броске Удачи и только один раз за бой (право сгорает при отказе — см. `combat_mechanics.md`, §6):

```
⚠️ Твоё HP критически низкое! (18/85)
🍀 Проверка удачи на побег: 7 → есть шанс уйти живым!

[🏃 Сбежать]   [⚔️ Биться дальше]
```

Если бросок не удался — побег не предлагается, фаза идёт как обычно:

```
🍀 Проверка удачи на побег: 2 → шанса уйти нет в этот раз.

[🎲 Атаковать]
```
